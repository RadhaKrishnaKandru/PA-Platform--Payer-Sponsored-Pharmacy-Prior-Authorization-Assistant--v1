# . What each node does

# 1. extract.py — Prescription extraction
# LLM + Pydantic
# Reads the submitted eRx and extracts drug name, NDC, quantity, days supply, prescriber and diagnosis. Validates the extracted fields before returning them.

# Output: rx




# 2. coverage.py — Coverage verification
# Python + PostgreSQL
# Checks whether the member is eligible under the relevant plan and date. Does not need an LLM.

# Output: coverage, potentially status




# 3. policy.py — Policy retrieval and interpretation
# PostgreSQL + Chroma + LLM
# Looks up the formulary rule, retrieves relevant policy chunks, and interprets the supporting evidence. Checks that citations refer to retrieved documents.

# Output: policy




# 4. gaps.py — Documentation gap analysis
# Python rules + LLM
# Compares the policy's documentation requirements with the information available in the case. Identifies missing clinical notes, lab results or other required evidence.

# Output: gaps




# 5. utilization.py — Utilization checks
# Python + PostgreSQL
# Checks refill timing, quantity limits, potential duplicate therapy and relevant claims history. Returns review signals rather than asserting misuse.

# Output: utilization




# 6. guardrail.py — Safety validation
# Deterministic validation
# Checks generated content for unsupported claims, invalid citations and prohibited approval, denial or medication-recommendation language. Manages the retry and safe-fallback behavior.

# Output: guardrail_passed, guardrail_attempts




# 7. provider_msg.py — Provider communication
# LLM + template
# Drafts a fax, email or portal message requesting the specific missing documentation. It does not send the message.

# Output: provider_msg




# 8. summary.py — Final summary
# Python
# Combines validated outputs into the response consumed by your React dashboard. Preserves manual-review and stopped statuses.

# Output: summary
